**Q2. Safety argument and implementation.** The argument is correct as stated: given (G), each step (counting
conditions, propagation, partial rule, cross-role rule) emits only true pairs. I checked it step by step against
`_settle` (`:1106-1167`). The counting test is `len(anchored) != len(takers) or len(open_uses) != len(open_markers)
or len(open_uses) > 1`. Propagation only fixes a use with one option or a marker with one taker. Every removal that
leaves a use or marker with no option returns None. Acceptance requires `fixed_u == anchored`. `_same_name` restricts
support to the class (`own`), applies the cross-role rule before settling, and applies the partial rule per class.
The implementation matches the model. Support is a superset of the exact relation, with one exception: R-04. Every
wrong link I could build is a violation of (G). That means a marker that does not show its own use's text, plus a
coincidence (another marker shows that text, and the partner has no readable text): R-02. Areas I tried without
finding another route:
* restyled values: digit groups (`,`, `٬`, NBSP, thin space), Arabic-Indic and Persian digits, case, U+2212, units
  and qualifiers before or after: covered;
* `+1.31` against `1.31`, `–` ranges against `-`, `45.5 %`: covered by the number run when the digits number 3 or
  more;
* `5 %`, `٪`, a rounded value, scientific notation, a reformatted date: not covered, and they swap only with the
  R-02 coincidence;
* cut texts. `ANCHOR_KEEP`: a cut prefix lets an anchor match at position 0 inside a word, which only adds support
  (the safe direction). `ANCHOR_SOURCE_MAX`: a cut inside a ref, comment, link or template leaves `<`, `>`, `|` or
  unbalanced braces, so the anchor becomes None (the use becomes open). With several such uses the class abstains
  (I saw this while building `s09_perf.py` with 500 refs in one parameter; that variant was not kept);
* several names in one transclusion are settled independently; several roles go through the cross-role rule;
* Arabic diacritics are not folded, so a template that dropped them would fall under R-02. I know of no template
  that does.

**Q3. New code paths.**
* Grouping by `about`: no double claim and no cross-transclusion pairing (above). A pre-existing point, not from the
  fixes (hypothesis, not reproduced): a literal `<ref>` written between the parts of a multi-part transclusion is a
  prose use, but its marker is in the transclusion's `ren` list. The count-only anonymous rule could then pair it with
  a template use whose own marker is not shown. `_anchor_contradicts` now guards that pair when the texts can be read.
* `_anchor_contradicts`: correct for anonymous uses. It is not applied to named template-generated uses (R-01).
* `_repeated_nested`: the undo clears `use_match`, `render_use_matched` and `use_basis` together and re-pairs through
  `_pair`. Containers are computed after it (`_containers()` at the end of the nested loop). In 207 real bundles no
  accounting check fails and no marker is matched twice (`out_s06_*.txt`). A double claim would need `_align` to pair
  an anonymous template-generated nested use with a marker of the repeated name by position. I could not build one
  (equal counts make the name an anchor key). If it happened, the one-to-one check would fail loudly.
* `_bibliography`: no wrong item and no G7 route found (above).
* Issue filter: sound (above).
* Walk cache: the key `(block, max_nodes)` holds the lxml elements themselves, so proxies stay alive and identity is
  stable. A marker that the block pass does not reach (inside hidden content) falls back to `_walk_to`. One change of
  behaviour, in the safe direction: a block of more than `ANCHOR_MAX_NODES` nodes now gives no prefix to any of its
  markers, also to early ones that the old walk reached.
* `secret_gate.py`: R-03.
