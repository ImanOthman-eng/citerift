# Stage 03 simulation report

Simulated results are kept apart from empirical ones. Every number in this file comes from SYNTHETIC
scripted inputs run against the production code; none of it is a measurement of Wikipedia or of the evaluation
sample (those are in `TEST_RESULTS.md` and `evaluation/`). The initial simulation plan is section 7 of
`design/INITIAL_SPECIFICATION.md`.

## 1. What is simulated and why

| Simulation | Question | Production code exercised | Independent part |
|---|---|---|---|
| Fetch policy (`simulations/stage03/fetch_policy_sim.py`) | Can any scripted sequence of answers, errors, timeouts and Retry-After values make the client retry earlier than allowed, exceed its attempt or deadline budget, return a failure as an answer, or lose a `not_before`? | `citerift.wiki.fetch.Fetcher` with a simulated clock and a scripted transport | a reference model of the retry schedule written from SPECIFICATION.md section 8, without calling the production planner |
| Reconciliation perturbation (`simulations/stage03/reconcile_perturbation_sim.py`) | When a render differs from the saved source as real renders do, does the source/render join ever attach a use or a container to someone else's footnote? | the complete extractor (`extract_bundle`) on generated bundles | the expected attachment is encoded in each generated marker id, so a wrong join is detected without the extractor's logic |
| Fault injection (tests) | Does an interruption while publishing a bundle or an output leave a partial or replaced result? | `bundle.publish_bundle`, `bundle.publish_file` | monkeypatched write and rename steps (`test_wiki_bundle_verify.py`) |

## 2. Fetch-policy simulation

Command (the same at every revision cited below):

```bash
uv run python simulations/stage03/fetch_policy_sim.py 5000 20261028
```

Each of 5000 seeded sequences scripts up to three answers drawn from: accepted JSON, HTTP 429/500/502/503/403/404
with or without Retry-After (seconds or HTTP date), MediaWiki maxlag and other API errors in HTTP 200, timeouts,
truncated JSON, oversize bodies and gzip bombs. The policy is the production one with small byte limits
(10 s interval, 3 attempts, 30 s per operation, 180 s per capture).

Invariants checked on every sequence:

- **I1:** the minimum interval holds between attempts.
- **I2:** Retry-After is never shortened.
- **I3:** at most three attempts.
- **I4:** no attempt starts at or after the deadline.
- **I5:** an answer is returned only after an accepted attempt.
- **I6:** a failure never carries a body.
- **I7:** a deferred result's `not_before` is no earlier than asked and lies past the deadline.
- **I8** (added in the second review round, RF-25): an operation that ends `ATTEMPTS_EXHAUSTED` after a Retry-After
  records a `not_before` that is no earlier than asked.

Besides the invariants, the attempt count and the final code are compared with the reference model.

| Code | Failures | Outcomes (5000 sequences) |
|---|---|---|
| before RF-25 (`e9b7cfa`), I8 added | 250, all "I8 exhausted after Retry-After without not_before" | (kept in `review/failfirst/round2/before/sim-fetch_policy_I8.json`) |
| after RF-25 (`d626c06`) | 0 | accepted 2648, ATTEMPTS_EXHAUSTED 542, DEFERRED_RETRY_AFTER 467, HTTP_FORBIDDEN 387, HTTP_NOT_FOUND 366, RESPONSE_TOO_LARGE 324, API_ERROR 266 |

A Retry-After that cannot be read or lies beyond one year (RF-24) is not generated by this simulation; unit tests
cover it (`test_wiki_review_regressions.py::test_wiki_retry_after_dates_and_ranges` and
`test_wiki_an_unusable_retry_after_is_never_replaced_by_a_shorter_backoff`). The network gate between processes
(RF-25) is covered by tests with real lock files (`test_wiki_fetch_capture.py`, `test_wiki_review_regressions.py`),
not by this simulation.

## 3. Reconciliation perturbation simulation

Command:

```bash
uv run python simulations/stage03/reconcile_perturbation_sim.py 200 20261028
```

200 generated articles (named and anonymous refs, reuses, groups) are each rendered faithfully and with four
perturbations: one marker dropped, one extra marker from a template, one marker moved, two notes sharing one id.
Measured per perturbation over 1823 source uses:

| Perturbation | Wrong use links | Wrong notes | Linked | Abstained | Same-reference swaps |
|---|---|---|---|---|---|
| none | 0 | 0 | 1823 | 0 | 0 |
| drop_marker | 0 | 0 | 1121 | 702 | 0 |
| extra_marker | 0 | 0 | 1550 | 273 | 0 |
| move_marker | 0 | 0 | 1212 | 504 | 107 |
| shared_note_id | 0 | 0 | 1823 | 0 | 0 |

The same numbers were obtained before and after the second review round (`e9b7cfa` and `a29bb4e`). The RF-07
fix (first round) had reduced wrong use links from 11 in 60 articles to 0; its evidence is in
`review/failfirst/RF-07_*`.

How to read the table:

- **Abstention is the price of never guessing.** With one marker moved, 504 of 1823 uses are left unlinked rather
  than risk a wrong attachment.
- **A same-reference swap** links a use to another use's marker of the *same* reference. The container, its note
  and its marker observation are correct, but at the use level it counts as a link to a different marker.
  FROZEN_PROTOCOL.md gate G6b counts it as a false attachment. It arises only when a marker is moved, which the
  generated renders do on purpose; whether real Parsoid output ever moves a marker is measured on the holdout, not
  here.
- **With a shared note id**, every use is still linked to its own marker, and the two containers that claim the
  note are `note_ambiguous`, with no region attached (RF-03).

## 4. Fault injection

| Case | Result |
|---|---|
| interruption while writing an artifact, `capture.json`, or at the final rename | nothing at the target, no temporary left, an existing valid bundle byte-identical |
| a directory appears at the target during publication (RF-33) | refused (`BUNDLE_PATH_UNSAFE`); the directory is left as found |
| interruption while writing an output file | no partial file |
| worker past its wall deadline, over its memory limit, exiting at the deadline | `EXTRACTION_DEADLINE_EXCEEDED` / `EXTRACTION_MEMORY_EXCEEDED`; the kill tolerates an already-ended process |

## 5. Limits of these simulations

- The generated articles use a small grammar (`<ref>` tags, names, groups, reuses). They do not contain templates
  that generate references, list-defined references or bibliography entries; those are covered by tests and by
  the holdout.
- The fetch simulation scripts the transport. It does not exercise TLS, DNS, the proxy or the socket-level read
  deadline (RF-28, tested with a local HTTP server).
- Simulation agreement with the reference model shows consistency with the specification as written, not that
  the specification matches Wikimedia's behavior.
